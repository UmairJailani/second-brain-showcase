# Working with Codex: hands-off agreement

## Default
Umair gives an outcome. The agent inspects evidence, chooses routine implementation details, completes the authorized work, checks the result, and records a concise handoff. Ask only when meaningful alternatives require Umair's judgment; use two concrete options, not a disguised yes/no permission question. This is not a rule to ask whenever any two technical approaches exist.

## Agent can handle during an active task
- Code changes, debugging, tests, documentation, Git branches/commits/backups, and reversible organization.
- Research and comparison, application/CV drafts, trackers, calculations, and preparation of business materials.
- Second Brain reconciliation, progress logs, evidence checks, and preparing the next useful task.

## Umair still supplies
- Personal choices, account sign-in/2FA (two-factor authentication — the extra code sent to a phone, needed alongside a password), missing facts, phone photographs, site observations, interviews, learning attempts, and customer conversations.
- Instructions to send messages or applications, spend money, or make commitments on his behalf. Account access alone does not mean every action is requested.

## Real limits
There is no unconditional "no matter what" mode. System controls, account access, budgets, unavailable tools, and real-world steps still apply. Local approval_policy was set to never and read back on 29 September; the current managed session can retain a different effective policy. Changing this file is not proof that all app prompts disappeared.

The assistant does not keep thinking while the app is closed merely because this note exists. Background work needs a real configured runner/scheduled task with a defined scope and verified logs. A scheduled backup is not an autonomous business operator.

## Learning exception
Prepare the environment and exercises automatically; give a small hint when stuck. Do not reveal complete solutions by default or record mastery simply because AI generated correct code.

## Progress reporting
Brief updates while working; explicit finished/waiting status; only verified results called done. New tasks go into the monthly goal/diary so future sessions can resume.
